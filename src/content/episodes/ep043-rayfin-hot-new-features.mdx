## Summary

Mike brings on Chris Anderson, a PM from Microsoft on Rayfin, to catch up people who missed FabCon. Chris walks through a real v1 of the connector model, covering semantic models, SQL, the warehouse, and the lakehouse, with access either as the signed-in user or as an item identity. Functions and secrets finally give apps a backend, so keys and API calls stay off the browser. They then look at the 1.3.6 local dev flow and the GitHub Copilot plugin, which uses the Rayfin CLI's auth so agents are not stuck on a login prompt. Chris shows a custom Azure DevOps board his team built, and they close on when to build instead of buy, and on the shadow-IT pressure that shows up when procurement is slow.

## Key Takeaways

- ▸ The new connector model is the v1 Chris wanted at Build: semantic models, SQL, warehouse, and lakehouse, with the app connecting as the user or as a service identity.
- ▸ Functions and secrets keep OpenAI keys and other backend work off the client, including a call back into Fabric to refresh a pipeline or drop a file in the lakehouse. First-class OneLake file storage was not in the version that launched. Chris put it at probably 137.
- ▸ Rayfin dev in 1.3.6 runs Vite, a proxy, and functions locally, and signs the session in from the CLI so embedded Copilot and VS Code browsers stop prompting for login.
- ▸ The universal template ships skills for React structure and accessibility so an agent does not leave a pile of cleanup for people who are not professional web developers.
- ▸ Azure DevOps is reachable from functions, with auth constraints still in place. Chris's team uses that to build the Gantt and status views ADO does not put on one screen.
- ▸ Agents make a first version cheap, but support, legal, and compliance still count. Rayfin's bet is a front end on data that is already in Fabric, which is also why a slow procurement process pushes people to build their own.
