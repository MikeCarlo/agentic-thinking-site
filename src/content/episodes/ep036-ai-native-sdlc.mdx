## Summary

Mike and Mathias use Anthropic's AI-native SDLC playbook as the spine of the episode. The provocative claim is that agents have collapsed the coding step, so planning, testing, QA, and production feedback are the new bottlenecks. Anthropic keeps the same six stages — plan, design, build, test, deploy, and maintain — but runs them as a continuous loop instead of a linear release train. They spend the rest of the hour on what that means in practice: review the spec while it is still a document, manage agents the way you would an offshore team, and compact context before quality falls off.

## Key Takeaways

- ▸ Anthropic's playbook says agents solved the coding problem, so the remaining SDLC work is everything around the code: planning, testing, QA, bug bash, and feeding real user feedback back to the agents.
- ▸ The six stages stay the same. What changes is the shape: traditional SDLC is a linear release cycle, and the AI-native version is a loop that can kick off the next change from production signals without waiting for a human to start a new project.
- ▸ The expensive mistake is a bad spec. Correcting a text document is cheap; unwinding a pull request with hundreds of thousands of generated lines is not, so spec review is the engineering skill that matters more now.
- ▸ Mike's own loop pairs an agent plan with pen.dev so UI design and the feature spec move together instead of design arriving after the code.
- ▸ Day-to-day work shifts from clicking through Excel or an inbox to managing the agent that does that work. The human job is direction and review, closer to managing an overnight offshore team than to typing the change.
- ▸ One Uber write-up they cite treats about 400k tokens as the compaction point on a 1 million token window. Letting context grow past that sweet spot is where they saw quality drop.
