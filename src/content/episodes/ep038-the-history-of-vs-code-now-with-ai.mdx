## Summary

Mike, Mathias, and Ryan pick up the VS Code documentary at the AI chapters they paused last episode. The team on screen compares early Copilot to cruise control — you still steer — and the later models to self-driving, where the developer is no longer responsible for every line. They walk through agent mode, custom models, open-sourced chat, skills, and MCP, then the awkward fact that Cursor, Antigravity, and other forks are built on the same open editor. The close is that VS Code won by dogfooding and letting anyone contribute anywhere in the project, which is easier now that agents can help someone step outside a narrow role.

## Key Takeaways

- ▸ Early AI in the editor was cruise control: completions help, and the developer still sets speed and direction. Agent mode is the step change, closer to a self-driving car, because the model chooses when to call tools and can write the code.
- ▸ The documentary's timeline is compressed. In roughly a year the product moved through agent mode, custom models, open-sourced chat, completions in the open repo, instruction files, skills, and MCP, while the model names went from GPT-4o and Sonnet 3.5 to Sol, Opus 5, and Fable.
- ▸ Copilot worked in part because the VS Code team dogfooded it on their own large project. Patterns they felt while building the editor showed up as completions for everyone else.
- ▸ Forks such as Cursor and Antigravity skip some of the security and maintenance cost of the upstream editor, and the panel still treats that competition as useful. Weekly VS Code updates and faster bug fixes are the part developers actually feel.
- ▸ Open source plus a team that lets anyone touch any part of the product is the decision they want to copy. Agents make that less theoretical, because a person is no longer stuck as only the tester or only the UI owner.
