## Summary

Mike and Matthias return to the news desk after a break, covering Fable's arrival in GitHub Copilot with metered access and Anthropic extending the window for spending subscription quota on it. The main segment separates the tool-call loop that has always been inside an agent from the newer "loop engineering" idea, where a second agent decides what to send back when the first one claims it is done -- natural evolution, they argue, rather than hype, but one whose token cost turns it into a genuine engineering problem. They close on designing AI into specific business workflows instead of throwing it at everything, the shift from execution to relevance as the real bottleneck, and the mental-health cost of agents that are always available.

## Key Takeaways

- ▸ Fable is usable in GitHub Copilot with metered access, and Anthropic extended the period in which subscription quota covers it rather than a separate credit balance.
- ▸ Kimi 2.7 is the first open-weight model generally available in GitHub Copilot, at a substantially lower price point, though its 250K context window is a step down from the frontier norm.
- ▸ Ollama Cloud hosts open-weight models too large for local hardware, exposes an OpenAI-style REST endpoint, and offers a free tier with a no-retention, no-training guarantee.
- ▸ The request/tool-call/response cycle has always been a loop; loop engineering is the higher-level loop that decides how to respond when the agent reports a supposedly final result.
- ▸ Cost is the binding constraint on agent swarms -- the engineering skill is using expensive models selectively and offloading everything else to cheaper or free ones.
- ▸ Better tooling made building cheap, so the bottleneck moved from execution to relevance, and always-on agents raise a mental-health question the hosts plan to revisit in its own episode.
